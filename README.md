# claude-tuner

> **你的 Claude，工具和上下文都由你定。**

接第三方上游这件事，别人已经做完了（填个地址和 Key 就够了）。它们大多停在那儿：
接到**哪个**模型归你管，模型**看到什么**不归你管 —— 每一轮请求都带着一份写死的工具说明和上下文，
你用不上，却一直在为它付钱，也占着本该用来干活的注意力。

这个项目在本地起一层网关，把后一半还给你：

- **要哪些工具、不要哪些** —— 按功能分成一组组独立开关（界面遥控、终端面板、PR 与 CI、设计稿同步…）。
  关掉哪一类，配套的系统提示词段落也跟着走；**不在名单里的一律退回客户端原样**，
  读 / 写 / 执行这类核心工具则锁死剥不掉。
- **上下文怎么算** —— 客户端每轮都会塞进当前时间、Git 快照、计费版本号，你隔久了回来它还会把历史里的
  思维链剥掉。这些都会让上游的缓存命中不了，逐项处理掉。
- **接哪个上游** —— DeepSeek 官方、中转站、自建反向代理都行；模型映射、环境变量、客户端该读的几份配置，
  都收进下面这一个网页。

改的地方只有一个：一个跑在 `127.0.0.1` 上的网页。

```bash
curl -fsSL https://raw.githubusercontent.com/ls-open/claude-tuner/main/install.sh | bash
```

装完浏览器会自动弹出配置台，填一个 API Key 就能用。

> **我们不重做客户端，只把「哪些生效」交给你。** 这套客户端的工具设计、提示词与缓存策略本身是扎实的，
> 我们没有另写一套来替代它 —— 网关只是在它和上游之间加一层你能调的中间层：规则逐条可关，
> 关掉就退回客户端原样，工具面也一样。所以这里没有「换成我们的做法」，只有「这几十项，你想留哪些」。

> **「工具面应该由你来定」不是我们一家的怪癖**：DeepSeek 官方的 Harness 默认给模型 20 多个工具，
> 另外单独留了一个**只有两个工具**的模式（他们的口径是拿它跑基准测试），和一个能自己拼工具面的 Creator 模式。
> 我们比它再细一档：档位只是入口，底下每一类都是独立开关，还能退回客户端原样。

> ⚠️ **需要 API Key（3P / 开发者接入模式）**。官方网页账号（Pro / Team 邮箱直接登录）用不了 ——
> 那条链路是闭源的，落不了自定义接入点。其余边界见[装之前先确认](#装之前先确认)。

## 它具体改什么

### 1. 工具面：每轮都在重复发送的固定开销

客户端会把**每个可用工具**的说明一起发出去，无论这一轮用不用得上。开着的扩展越多，这份固定开销越大。
网关按功能把可精简的工具分成一组组开关：

- **关一类，省一类** —— 每一类在每轮请求里都占一份静态上下文。
- **剥工具会连带删掉它的说明段落** —— 工具没了、解释它的提示词还在，模型会被引到一个不存在的工具上，
  那比不剥更糟。这个耦合由代码维护，不由文案维护。
- **核心工具锁死** —— 代码读写、终端执行、文件检索（Bash / Read / Write / Edit / Glob / Grep 等）
  在受保护名单里，任何配置都剥不掉。
- **不在名单里的一律原样透传** —— 客户端升级后新增的工具，默认保留，不会被我们悄悄动手。

### 2. 上下文：让前缀尽可能保持字节恒定

上游的 Prompt Cache 按**前缀字节**命中。只要前面有一个字节变了，后面全部重算 —— 又慢又贵，
差价随上游不同，DeepSeek 官方那边是几十倍量级。客户端恰好每轮都在往前缀里塞会变的东西，
以及隔久了会从历史里剥掉思维链。这一组把它们逐项抹平：

- 动态日期、Git 状态快照、计费版本号标记、剩余额度计数行；
- 历史里丢失的思维链按记录补回来；
- 连通性探针本地秒回，不上云、不扣费。

> **不承诺命中率。** 能省多少取决于上游的缓存有效期和你自己的使用节奏，两头都不是这个项目能定的。
> 它保证的只是「让前缀尽可能保持字节恒定」这个手段 —— 数字请大家在自己的账单里看。

### 3. 上游接入：一个网页

- DeepSeek 官方（`/anthropic`）、OpenCode、各类官方模型中转站、自建反向代理，填个 Key 一键即用。
- 一键拉取服务商支持的模型列表，**真机连通性逐个测试**：通不通、耗时多少、返回什么，一目了然。
- 客户端模型选择器直接读你的映射配置：配几项，界面上就显示几项。

## 配置台

访问 **<http://127.0.0.1:8789/>** 进入调控台。

> 清理了 Cookie 或提示访问令牌时，运行以下命令获取带 Token 的访问链接：
> ```bash
> python3 ~/.claude/skills/claude-tuner/scripts/webui.py --url
> ```

每个开关旁边都标注了**生效时机**：

| 标记 | 写入哪里 | 涵盖 |
|---|---|---|
| **立即生效** | 网关自己的配置 | 前缀稳定化、工具精简 |
| **新会话生效** | 客户端设置 / 3P 配置 | 缓存保留时长、输入联想、终端联动、随附技能与工作流、定时任务 |
| **需重启客户端** | 3P 配置 / 桌面偏好 | 模型映射、1M 窗口、界面标签页 |

> 改动写在客户端**运行时会覆盖回去**的那几项时，如果 Claude 正在运行，页面会拦下并提示先退出客户端。

### 实时战绩

直接取上游返回的 `usage`，不搞估算：

- Prompt 缓存命中率与请求数；
- 命中缓存与未命中的 Token 分类统计；
- 工具精简**每次请求平均剥离多少个工具定义**（累计次数另计 —— 同一个工具每轮都重计一遍，
  只报累计数会给出一个看着不成立的大数字）。

## 装之前先确认

> ⚠️ **适用场景与协议要求**
> - **✅ 适用对象**：用 **API Key（Claude 桌面端 3P / 开发者接入模式）** 的用户。支持 Anthropic 官方
>   API Key、第三方兼容模型（如 DeepSeek）、中转站与自建反向代理。
> - **🚫 不适用对象**：在桌面端直接使用**官方网页账号（Pro / Team 邮箱登录）**的场景。那条通道闭源，
>   无法自定义接入点。
> - **⚡️ 协议要求**：上游必须原生支持 **Anthropic Messages 协议**（如 DeepSeek 填
>   `https://api.deepseek.com/anthropic`）。本项目**不做** OpenAI 格式到 Anthropic 格式的转译，
>   填 `/v1/chat/completions` 会报错。
> - **🍎 系统环境**：当前版本专为 **macOS** 打造（依赖 macOS 的配置文件路径、进程锁判定与套接字生命周期）。

## 安装

> **先做一件事：打开一次 Claude，进到界面，然后退出。**
> 刚从官网下载、还没启动过的客户端，它的配置目录还不存在。客户端第一次启动会自己建一遍，
> 先让它建完，我们再往上改 —— 顺序反了分不清谁盖谁。（安装脚本检测到这种情况也会提醒你。）

```bash
curl -fsSL https://raw.githubusercontent.com/ls-open/claude-tuner/main/install.sh | bash
```

1. 运行安装命令，脚本会引导你输入 Key（也可以回车跳过，稍后在网页里填）。
2. 浏览器自动打开配置台，选服务商、填 Key、点测试连接。
3. 点右上角「保存更改」，然后**完全退出 Claude 再重新打开**（菜单里的「退出」，不是关闭窗口）。

> 浏览器没自动打开时，直接访问 **<http://127.0.0.1:8789/>** —— 第一次打开后浏览器会记住授权，不用反复找链接。

**网络连不上 GitHub 时**：安装脚本内置多重备用通道。若全不通，可在仓库 `Code → Download ZIP`，
解压后执行 `bash install.sh`。

**验证是否生效**：

```bash
tail -5 ~/.claude-tuner/logs/gateway.log
```

看到 `"event": "upstream_ok"` 即代表链路通畅。

## 常见问题

**Q：我直接在桌面端登录官方网页账号（Pro / Team），能用吗？**
A：**不能**。官方网页登录走的是内部闭源认证链路，无法自定义上游和中转。本项目专为
**API Key（3P 开发者模式）** 设计。

**Q：关掉那么多工具，会影响写代码、读写文件吗？**
A：**不会**。Read / Write / Edit / Glob / Grep / Bash 以及核心 Agent 调度都在受保护名单里，
任何配置都剥不掉。可精简的只有分屏、窗口遥控、设计稿同步这类辅助工具。

**Q：网络搜索到底开还是关？**
A：先说明它是怎么工作的：**WebSearch / WebFetch 是服务端工具** —— 客户端只把工具定义发出去，
真正去搜、去抓的是**上游**。所以：

- 工具定义**一直都在**，开不开开关的区别是它占不占那份上下文；
- 能不能真用起来，取决于你的上游有没有实现这两个服务端工具 —— 有的中转实现了，有的没有；
- WebSearch 官方口径是 US-only，WebFetch 需要页面公开可访问（内网、要登录的拿不到）。

所以：上游实现了、你也需要，就留着；纯代码或离线场景，关掉能省一份固定上下文。

**Q：装完之后没生效？**
A：绝大多数是没有完全重启客户端。必须在 macOS 菜单栏点「退出 Claude」再打开（只按红叉关窗口不算）。
少数选项是**新会话生效** —— 保存后开一个新的对话即可，不用重启。

**Q：网关挂了怎么办？**
A：客户端的上游地址就指着本机网关，网关不在它会连不上上游、直接报错。保活是自动的：
客户端每次启动会话、你每提交一条消息之前都会跑一次保活钩子，发现网关不在就拉起来。
所以多数情况下你重发一条消息它就回来了；也可以在配置页一键重启网关。

**Q：为什么 DeepSeek 官方建议开自动压缩，而你们建议关掉？**
A：先把话说明白：上下文填满时压缩一次，**压缩那一次会把已有缓存丢掉、之后重新建立** ——
而不是「历史被改坏了」（那是把正常行为说成缺陷）。所以它是个取舍：换到 1M 大窗口之后压缩本来就很少触发，
而每次触发都要让你重新付一遍前缀的钱，我们倾向关掉；你要是经常把上下文跑满，留着更稳。

**Q：为什么只支持 Mac？**
A：本项目依赖 macOS 的桌面端配置路径、进程锁判定与 Unix 套接字生命周期管理。
Windows 下的文件锁与进程行为差异较大，首版专注 macOS。
